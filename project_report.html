1 مقدمة

وصف موجز للمشروع

مشروع "ملاذ" هو تطبيق ويب متكامل مبني بلغة PHP باستخدام نمط المعمارية MVC (Model-View-Controller)، يهدف إلى توفير منصة رقمية آمنة ومتخصصة للمرأة. تتيح المنصة للمستخدمات التواصل المجتمعي، قراءة المقالات المتخصصة، ومشاركة تجاربهن الشخصية ضمن بيئة داعمة وخالية من الأحكام.

يعمل المشروع على خادم محلي باستخدام XAMPP مع قاعدة بيانات MySQL، ويتضمن واجهة أمامية تفاعلية مبنية بـ HTML5 وCSS3 وJavaScript مع استخدام Fetch API للعمليات غير التزامنية.

أهمية المشروع

تعاني المرأة في كثير من الأحيان من شُح المساحات الرقمية الآمنة التي تناسب احتياجاتها وتحترم خصوصيتها. تبرز أهمية مشروع "ملاذ" في عدة محاور:

  • الأثر الاجتماعي: يسد فراغاً حقيقياً بتوفير مجتمع رقمي نسائي آمن وموثوق.
  • الأثر النفسي: يمنح المرأة مساحة للتعبير الحر عن مشاعرها دون خشية الحكم أو التنمر.
  • الأثر المعرفي: يجمع محتوى متخصصاً في الصحة والنفس والدين والأكاديميا في مكان واحد.
  • الأثر التقني: يُظهر تطبيقاً عملياً متكاملاً لأفضل معايير تطوير الويب الحديثة.

الهدف العام للمشروع

يهدف المشروع إلى بناء منصة ويب وظيفية متكاملة تجمع بين:

  • توفير مجتمع رقمي تفاعلي يتيح للمستخدمات النشر والتعليق والتفاعل.
  • إدارة محتوى مقالي بنظام مراجعة وموافقة إدارية.
  • نظام تسجيل دخول وإدارة حسابات مستخدمين مع صلاحيات متعددة.
  • لوحة تحكم شاملة للمدراء لمتابعة النظام وإدارة المحتوى والمستخدمين.
  • تطبيق أعلى معايير الأمان في تطوير تطبيقات الويب.

2 فكرة المشروع

وصف واضح للفكرة

"ملاذ" هو موقع اجتماعي ومعرفي موجّه للمرأة، يرتكز على أربعة محاور رئيسية:

المحورالوصفالمجتمع المرتبط

يحتوي الموقع على ثلاثة أقسام رئيسية يصل إليها المستخدم عبر القائمة الرئيسية:

  • قسم المجتمع: منشورات تفاعلية من نوع (تنفيس / طلب نصيحة / سؤال) مع إمكانية الإعجاب والتعليق والحفظ.
  • قسم المقالات: مقالات متخصصة تمر بمرحلة مراجعة إدارية قبل النشر مع إمكانية الحفظ وعرض تفاصيل المقال.
  • الصفحة الشخصية: لكل مستخدمة ملف شخصي يعرض إحصائياتها ونشاطاتها ومنشوراتها المحفوظة.

المشكلة التي يحلها المشروع

المشكلة: غياب منصات رقمية متخصصة وآمنة تلبي الاحتياجات الفريدة للمرأة بعيداً عن البيئات الاجتماعية العامة التي قد تكون مصدراً للضغط والحكم.

الحل الذي يقدمه ملاذ:

  • مجتمع مغلق ومتخصص يضمن خصوصية أعلى وتفاعل أكثر إيجابية.
  • محتوى منقّح ومعتمد يضمن الجودة والمصداقية عبر نظام الموافقة الإدارية.
  • تصميم مستوحى من ثقافة المرأة العربية بألوان دافئة وواجهة مريحة.
  • ميزات حفظ المحتوى المفضل للرجوع إليه لاحقاً.

3 تحليل المتطلبات

أولاً: المتطلبات الوظيفية (Functional Requirements)

نظام المصادقة (Authentication)

  • تسجيل مستخدم جديد باسم كامل وبريد إلكتروني وكلمة مرور.
  • تسجيل الدخول بالبريد الإلكتروني وكلمة المرور.
  • تسجيل الخروج وإنهاء الجلسة بشكل آمن.
  • التحقق من صحة البريد الإلكتروني وقوة كلمة المرور.
  • توجيه المستخدمين بعد تسجيل الدخول بناءً على الدور (مدير → لوحة التحكم، مستخدم → الصفحة المطلوبة).

نظام المجتمع (Community)

  • عرض قائمة المجتمعات المتاحة.
  • الانضمام إلى مجتمع أو مغادرته.
  • نشر منشور بأنواع مختلفة: تنفيس / طلب نصيحة / سؤال.
  • التعليق على المنشورات.
  • الإعجاب بمنشور وإلغاء الإعجاب.
  • حفظ منشور وإلغاء الحفظ.
  • حذف التعليقات.

نظام المقالات (Articles)

  • عرض المقالات المعتمدة مع الترقيم (Pagination).
  • تصفية المقالات حسب المجتمع.
  • تقديم مقال جديد مع رفع صورة غلاف.
  • حفظ المقال وإلغاء الحفظ (Bookmark).
  • عرض تفاصيل مقال كامل.

الملف الشخصي (Profile)

  • عرض بيانات المستخدمة وإحصائياتها.
  • تعديل الاسم والنبذة الشخصية.
  • رفع صورة شخصية جديدة.
  • تغيير كلمة المرور.
  • عرض المنشورات والنشاطات المحفوظة.
  • حذف وتعديل المنشورات الخاصة.

لوحة التحكم (Admin Dashboard)

  • عرض الإحصائيات العامة للموقع (مستخدمين، منشورات، تعليقات، إعجابات).
  • إدارة المستخدمين (عرض، حذف، تغيير الدور).
  • إدارة المنشورات (عرض، حذف).
  • مراجعة المقالات المعلّقة (قبول / رفض).

ثانياً: المتطلبات غير الوظيفية (Non-Functional Requirements)

المتطلبالتفاصيلالتطبيق في المشروع

الأداء تحميل سريع وتفاعل فوري Fetch API للعمليات غير التزامنية، Singleton Pattern لاتصال قاعدة البيانات
سهولة الاستخدام واجهة بديهية وتجربة مستخدم ممتازة تصميم عربي RTL، Glassmorphism، تأثيرات Hover، رسائل تأكيد/خطأ واضحة
الاستجابية تعمل على جميع أحجام الشاشات CSS Media Queries، Flexbox، Grid

كيفية بناء النظام

1. نقطة الدخول والموجّه (Entry Point & Router)

يعيد ملف .htaccess توجيه جميع الطلبات إلى index.php الذي يُسجّل المسارات ويستدعي الـ Router لمطابقة الطلب الوارد مع المتحكم المناسب.

2. طبقة المتحكمات (Controllers Layer)

كل متحكم يرث من App\Core\Controller التي توفر دوال مشتركة مثل view() لعرض الـ Views وredirect() للتوجيه وrequireAuth() / requireAdmin() للحماية.

3. طبقة النماذج (Models Layer)

كل نموذج يرث من App\Core\Model التي تحصل على اتصال PDO من Database::getInstance(). جميع الاستعلامات تستخدم Prepared Statements حصراً.

4. ربط الواجهة الأمامية بقاعدة البيانات

تتدفق البيانات كالتالي: الـ View تعرض HTML ← المستخدم يتفاعل ← POST/GET إلى الـ Router ← Controller يستدعي Model ← Model يستعلم MySQL ← Controller يمرر النتائج للـ View.

مثال على عملية التسجيل:

// 1. View: form submits POST to /register // 2. AuthController::handleRegister() \csrf_verify(); // التحقق من رمز CSRF $email = trim($_POST['email']); if (!filter_var($email, FILTER_VALIDATE_EMAIL)) { ... } // 3. UserModel::create() — Prepared Statement $hash = password_hash($password, PASSWORD_DEFAULT); $this->query("INSERT INTO users (name,email,password) VALUES (?,?,?)", [$name, $email, $hash]);

5. نظام API للعمليات التفاعلية (Fetch API)

عمليات الإعجاب والحفظ تتم بدون إعادة تحميل الصفحة عبر JavaScript:

// JavaScript: toggle like fetch('/malath-php-app/api/toggle_like.php', { method: 'POST', body: new FormData(formEl) }).then(r => r.json()) .then(data => { // تحديث عداد الإعجاب في الواجهة countEl.textContent = data.likes_count; });

8 شرح واجهات المستخدم

1. الصفحة الرئيسية (Landing Page)

تحتوي على Hero Section بتصميم تدريجي (Gradient) مع صورة جانبية وأزرار للانتقال للمجتمع أو اكتشاف البرامج. أسفلها قسم "ركائز ملاذ الأربعة" يعرض بطاقات تفاعلية Hover للمحاور الأربعة (صحة، نفس، دين، أكاديميا).

2. نظام المصادقة

واجهات تسجيل الدخول والتسجيل مبنية بنموذج مركزي على خلفية تدريجية. تظهر رسائل الخطأ باللون الأحمر مباشرة تحت الحقل المعني. عند إنشاء حساب ناجح، يظهر إشعار أخضر ويتم التوجيه تلقائياً لصفحة الدخول.

تفاعل المستخدم: ملء الحقول ← ضغط "تسجيل" ← التحقق من البيانات ← رسالة نجاح أو خطأ.

3. صفحة المجتمع

تنقسم إلى شريط جانبي يسار يحتوي قائمة المجتمعات مع أزرار الانضمام/المغادرة، والمنطقة الرئيسية تعرض المنشورات. كل بطاقة منشور تحتوي على صورة المستخدمة والاسم والتاريخ والمحتوى وأزرار (إعجاب ❤️، تعليق 💬، حفظ 🔖). النقر على "تعليق" يكشف قسم التعليقات دون تحميل الصفحة.

تفاعل المستخدم: الضغط على ❤️ يستدعي Fetch API فوراً ويحدث عداد الإعجاب دون أي تحميل.

4. صفحة المقالات

شبكة من بطاقات المقالات (3 أعمدة على الشاشة الكبيرة) مع صورة الغلاف والعنوان والكاتب والتاريخ والتصنيف. في الأعلى شريط تصفية حسب المجتمع، وفي الأسفل أزرار الترقيم. النقر على مقال يفتح صفحة مفردة كاملة.

5. لوحة التحكم (Admin Dashboard)

مقسمة إلى أربعة تبويبات عبر Query Parameter:

  • Overview: بطاقات إحصائية (إجمالي المستخدمين، المنشورات، التعليقات، الإعجابات) + آخر المنشورات والمستخدمين.
  • المستخدمون: جدول بجميع المستخدمين مع خيار الحذف وتغيير الدور.
  • المنشورات: جدول المنشورات مع خيار الحذف.
  • المقالات: قائمة المقالات المعلقة مع أزرار "قبول" و"رفض".

6. الملف الشخصي

يظهر في الأعلى بيانات المستخدمة مع صورتها وإحصائياتها (عدد المساهمات، المحفوظات). أسفله تبويبان:

  • نشاطاتي: سجل المنشورات والتعليقات والإعجابات.
  • المحفوظات: المنشورات والمقالات المحفوظة.

يمكن تحرير بيانات الملف الشخصي عبر نموذج منبثق يشمل تغيير الصورة والاسم والنبذة وكلمة المرور.

9 التحديات والحلول

التحدي المشكلة الحل المطبق
تطبيق MVC من الصفر بناء نظام Router مخصص يربط المسارات بالمتحكمات دون استخدام Framework جاهز كتابة Router Class تستقبل GET/POST ومطابقة URI بعد تنظيفه من prefix المشروع، مع ملف .htaccess لتوجيه جميع الطلبات لـ index.php
حماية CSRF نماذج POST عرضة لهجمات Cross-Site Request Forgery بناء ملف csrf.php مخصص يولد رمزاً عشوائياً 32 بايت لكل جلسة، يُدمج في كل نموذج POST ويتحقق منه قبل أي معالجة
رفع الملفات بأمان رفع صور المستخدمين قد يسمح برفع ملفات PHP ضارة التحقق من امتداد الملف (jpg/jpeg/png/webp فقط)، وتغيير اسم الملف تلقائياً باستخدام user_id + timestamp
عمليات Fetch API (AJAX) إجراء الإعجاب والحفظ دون تحميل الصفحة مع الحفاظ على الأمان بناء نقاط نهاية API منفصلة في مجلد api/، ترجع JSON وتتحقق من الجلسة وCSRF في كل طلب
تصميم RTL متكامل CSS الافتراضي مبني لـ LTR وكثير من المكتبات لا تدعم RTL بالكامل كتابة جميع CSS يدوياً مع dir="rtl" على HTML وتعديل padding/margin/flexbox لتناسب العربية
نظام الأدوار (Roles) منع المستخدم العادي من الوصول لصفحات المدير دالة requireAdmin() في Base Controller تتحقق من $_SESSION['user_role'] وترفض الوصول بـ 403 إذا لم يكن المستخدم مديراً
نظام إشعارات فوري إظهار عدد الإشعارات الجديدة في الهيدر دون تحميل الصفحة استدعاء api/notifications.php دورياً بـ setInterval من JavaScript يرجع عدد الإشعارات غير المقروءة
ترقيم صفحات المقالات عرض مئات المقالات دفعة واحدة يبطئ الصفحة LIMIT/OFFSET في استعلام SQL مع حساب totalPages وعرض أزرار الصفحات السابقة/التالية

الأخطاء التي تم اكتشافها وإصلاحها

  • مسار Router: كان المشروع يعمل على مسار متداخل (/malath-php-app/) مما يسبب اختلافاً في URI — تم حله بتنظيف الـ URI في Router::dispatch().
  • إرسال النماذج: بعض النماذج القديمة كانت تحتوي على .php في action — تم توحيدها لتعمل مع المسارات الجديدة.
  • CSRF في API: نقاط API لا تستخدم CSRF بالطريقة التقليدية — تم التحقق من الجلسة بدلاً منه.
