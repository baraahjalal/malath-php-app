## 1. مقدمة

### وصف موجز للمشروع

مشروع **"ملاذ"** هو تطبيق ويب متكامل مبني بلغة **PHP 8** باستخدام نمط المعمارية **MVC (Model-View-Controller)**، يهدف إلى توفير منصة رقمية آمنة ومتخصصة للمرأة. تتيح المنصة للمستخدمات التواصل المجتمعي، وقراءة المقالات المتخصصة، ومشاركة تجاربهن الشخصية ضمن بيئة داعمة وخالية من الأحكام. يتضمن المشروع نظام مصادقة متكاملاً مع ميزة "تذكرني"، ولوحة تحكم إدارية شاملة، ونظام إشعارات بريد إلكتروني تلقائي.

### أهمية المشروع

تعاني المرأة في كثير من الأحيان من شُح المساحات الرقمية الآمنة التي تناسب احتياجاتها وتحترم خصوصيتها. تبرز أهمية مشروع "ملاذ" في عدة محاور:

- **الأثر الاجتماعي:** يسد فراغاً حقيقياً بتوفير مجتمع رقمي نسائي آمن وموثوق
- **الأثر النفسي:** يمنح المرأة مساحة للتعبير الحر عن مشاعرها دون خشية الحكم أو التنمر
- **الأثر المعرفي:** يجمع محتوى متخصصاً في الصحة والنفس والدين والأكاديميا
- **الأثر التقني:** يُظهر تطبيقاً عملياً متكاملاً لأفضل معايير تطوير الويب الحديثة

### الهدف العام للمشروع

يهدف المشروع إلى بناء منصة ويب وظيفية متكاملة تجمع بين:

- توفير مجتمع رقمي تفاعلي يتيح للمستخدمات النشر والتعليق والتفاعل
- إدارة محتوى مقالي بنظام مراجعة وموافقة إدارية مع إشعارات بريد إلكتروني
- نظام تسجيل دخول آمن مع إدارة حسابات ومستويات صلاحيات متعددة
- لوحة تحكم شاملة للمدراء لمتابعة النظام وإدارة المحتوى والمستخدمين
- تطبيق أعلى معايير الأمان في تطوير تطبيقات الويب

## 2. فكرة المشروع

### وصف واضح للفكرة

**"ملاذ"** هو موقع اجتماعي ومعرفي موجّه للمرأة، يرتكز على أربعة محاور رئيسية:

| المحور | الوصف | المجتمع المرتبط |
|--------|-------|----------------|
| الصحة | برامج العناية بالصحة الجسدية والتغذية | المجتمع الصحي (health) |
| النفس | الدعم النفسي والتعبير الآمن عن الذات | المجتمع النفسي (psychological) |
| الدين | محتوى ديني وسطي يعزز القيم الروحية | المجتمع الديني (religious) |
| الأكاديميا | التمكين الأكاديمي والمهني وتحقيق الطموحات | المجتمع الأكاديمي (academic) |

يحتوي الموقع على ثلاثة أقسام رئيسية:

- **قسم المجتمع:** منشورات تفاعلية (فضفضة / طلب نصيحة / سؤال / تجربة) مع إمكانية الإعجاب والتعليق والحفظ والإبلاغ
- **قسم المقالات:** مقالات متخصصة تمر بمرحلة مراجعة إدارية قبل النشر مع إمكانية الحفظ وعرض التفاصيل
- **الصفحة الشخصية:** ملف شخصي لكل مستخدمة يعرض إحصائياتها ونشاطاتها ومنشوراتها المحفوظة

### المشكلة التي يحلها المشروع

**المشكلة:** غياب منصات رقمية متخصصة وآمنة تلبي الاحتياجات الفريدة للمرأة بعيداً عن البيئات الاجتماعية العامة التي قد تكون مصدراً للضغط والحكم.

**الحل الذي يقدمه ملاذ:**

- مجتمع مغلق ومتخصص يضمن خصوصية أعلى وتفاعل أكثر إيجابية
- محتوى منقّح ومعتمد يضمن الجودة والمصداقية عبر نظام الموافقة الإدارية
- إشعارات بريد إلكتروني تلقائية تُبقي المستخدمة على اطلاع بحالة مقالاتها
- تصميم مستوحى من ثقافة المرأة العربية بألوان دافئة وواجهة مريحة
- ميزات حفظ المحتوى المفضل للرجوع إليه لاحقاً
- نظام إبلاغ عن المحتوى غير الملائم للحفاظ على بيئة آمنة

### المستخدمون المستهدفون

| الفئة | الدور في النظام | الصلاحيات |
|-------|----------------|-----------|
| المستخدمة العادية | عضوة في المنصة | قراءة المحتوى، النشر، تقديم مقالات، تعديل الملف الشخصي، حفظ المحتوى، الإبلاغ |
| المديرة (Admin) | مشرفة على المنصة | إدارة المستخدمين، الموافقة/رفض المقالات، حذف المخالفات، عرض الإحصائيات |
| الزائرة (Guest) | زائرة غير مسجلة | تصفح الصفحة الرئيسية وصفحة المقالات (قراءة فقط) |

## 3. تحليل المتطلبات

### أولاً: المتطلبات الوظيفية (Functional Requirements)

#### نظام المصادقة (Authentication)

- تسجيل مستخدم جديد باسم أول واسم أخير وبريد إلكتروني وكلمة مرور
- تسجيل الدخول بالبريد الإلكتروني وكلمة المرور مع خيار "تذكرني" لجلسة دائمة
- تسجيل الخروج وإنهاء الجلسة بشكل آمن وحذف رمز "تذكرني"
- التحقق من صحة البريد الإلكتروني وقوة كلمة المرور (8 أحرف على الأقل، حرف كبير، حرف صغير، رقم، ورمز خاص)
- إرسال بريد إلكتروني ترحيبي للمستخدمة الجديدة تلقائياً عند التسجيل
- إرسال إشعار بريدي للمدير عند انضمام مستخدمة جديدة
- توجيه المستخدمين بعد تسجيل الدخول بناءً على الدور (مدير ← لوحة التحكم، مستخدم ← الصفحة المطلوبة)

#### نظام المجتمع (Community)

- عرض قائمة المجتمعات المتاحة الأربعة والانضمام إليها أو مغادرتها
- نشر منشور بأنواع مختلفة: فضفضة / طلب نصيحة / سؤال / تجربة
- التعليق على المنشورات والإعجاب بها وحفظها دون إعادة تحميل الصفحة
- حذف التعليقات والمنشورات الخاصة
- الإبلاغ عن المحتوى المخالف

#### نظام المقالات (Articles)

- عرض المقالات المعتمدة مع الترقيم (Pagination — 9 مقالات في الصفحة)
- تصفية المقالات حسب المجتمع
- تقديم مقال جديد مع رفع صورة غلاف
- حفظ المقال وإلغاء الحفظ (Bookmark)
- إرسال إشعار بريدي للكاتبة عند قبول أو رفض مقالها

#### الملف الشخصي (Profile)

- عرض بيانات المستخدمة وإحصائياتها (عدد المساهمات والمحفوظات)
- تعديل الاسم والنبذة الشخصية ورفع صورة شخصية جديدة
- تغيير كلمة المرور
- عرض المنشورات والتعليقات والمحفوظات في تبويبات منفصلة

#### لوحة التحكم (Admin Dashboard)

- عرض الإحصائيات العامة للموقع (مستخدمات، منشورات، تعليقات، إعجابات)
- إدارة المستخدمات (عرض، حذف، تغيير الدور)
- إدارة المنشورات (عرض، حذف)
- مراجعة المقالات المعلّقة (قبول / رفض) مع إرسال إشعار بريدي للكاتبة

#### صفحات عامة

- صفحة رئيسية تعريفية بالمنصة
- صفحة "من نحن" (About)
- صفحة "تواصل معنا" (Contact)
- صفحة "الأسئلة الشائعة" (FAQ)
- صفحة سياسة الخصوصية (Privacy Policy)
- صفحة الشروط والأحكام (Terms of Service)

### ثانياً: المتطلبات غير الوظيفية (Non-Functional Requirements)

| المتطلب | التفاصيل | التطبيق في المشروع |
|---------|---------|-------------------|
| الأمان | حماية من هجمات الويب الشائعة | Prepared Statements، htmlspecialchars، CSRF Tokens، password_hash، session_regenerate_id |
| الأداء | تحميل سريع وتفاعل فوري | Fetch API للعمليات غير التزامنية، Singleton Pattern لاتصال قاعدة البيانات |
| سهولة الاستخدام | واجهة بديهية وتجربة مستخدم ممتازة | تصميم عربي RTL، Glassmorphism، تأثيرات Hover، رسائل تأكيد وخطأ واضحة |
| الاستجابية | تعمل على جميع أحجام الشاشات | CSS Media Queries، Flexbox، Grid |
| قابلية الصيانة | كود منظم وسهل التطوير | MVC Architecture، Namespace، Autoloading |
| التواصل التلقائي | إبقاء المستخدمات على اطلاع | PHPMailer عبر SMTP لإشعارات التسجيل وحالة المقالات |

## 4. تصميم النظام

### خريطة الموقع (Site Map)

```
ملاذ — الصفحة الرئيسية (/)
│
├── تسجيل الدخول (/login)
│   └── تذكرني (Remember Me Cookie)
│
├── إنشاء حساب (/register)
│   └── بريد ترحيبي تلقائي
│
├── المجتمع (/community)
│   ├── نشر منشور (POST)
│   ├── الانضمام/المغادرة (API)
│   ├── الإعجاب / الحفظ / التعليق (API)
│   └── الإبلاغ عن محتوى (API)
│
├── المقالات (/articles)
│   ├── تقديم مقال (/article-create)
│   ├── مقال مفرد (/articles-single)
│   └── حفظ مقال (API)
│
├── الملف الشخصي (/profile)
│   └── تعديل البيانات (POST)
│
├── لوحة التحكم (/dashboard) — للمدراء فقط
│   ├── إحصائيات عامة
│   ├── إدارة المستخدمات
│   ├── إدارة المنشورات
│   └── مراجعة المقالات (قبول/رفض + بريد إلكتروني)
│
└── صفحات عامة
    ├── /about  /contact  /faq
    ├── /privacy
    └── /terms
```

### كيفية بناء النظام

#### نقطة الدخول والموجّه (Entry Point & Router)

يعيد ملف `.htaccess` توجيه جميع الطلبات إلى `index.php` الذي يسجل المسارات ويستدعي الـ `Router` لمطابقة الطلب الوارد مع المتحكم المناسب. يقوم الـ Router بتنظيف الـ URI من مسار التطبيق (`/malath-php-app`) ومطابقته مع المسارات المسجلة:

```php
// Router::dispatch() — تنظيف URI ومطابقة المسار
$uri = '/' . trim(str_replace('/malath-php-app', '', $uri), '/');
$uri = preg_replace('/\.php$/', '', $uri);
if ($uri === '/index') $uri = '/';
```

#### طبقة المتحكمات (Controllers)

كل متحكم يرث من `App\Core\Controller` التي توفر:
- `view()` — عرض ملف View مع تمرير البيانات
- `redirect()` — إعادة التوجيه
- `json()` — إرجاع استجابة JSON للـ API
- `requireAuth()` — التحقق من تسجيل الدخول، وإعادة التوجيه لصفحة الدخول إن لم يكن
- `requireAdmin()` — التحقق من الصلاحية الإدارية، وإظهار خطأ 403 إن لم تكن

#### طبقة النماذج (Models)

كل نموذج يرث من `App\Core\Model` التي تحصل على اتصال PDO من `Database::getInstance()` (Singleton). جميع الاستعلامات تستخدم Prepared Statements حصراً عبر دالة `query()`.

#### خدمة البريد الإلكتروني (EmailService)

تستخدم مكتبة PHPMailer عبر SMTP لإرسال ثلاثة أنواع من الإيميلات:
- **sendWelcome()** — ترحيب بالمستخدمة الجديدة عند التسجيل
- **sendNewUserNotification()** — إشعار المدير بانضمام مستخدمة جديدة
- **sendArticleStatus()** — إخبار الكاتبة بقرار قبول أو رفض مقالها

#### خدمة "تذكرني" (RememberMeService)

تُنشئ رمزاً عشوائياً آمناً، تخزن نسخة مشفرة بـ SHA-256 في جدول `remember_tokens`، وترسل رمز النص الصريح في Cookie بصلاحية 30 يوم. عند كل طلب، تتحقق من الرمز وتسجل دخول المستخدمة تلقائياً.

#### تدفق البيانات من الواجهة لقاعدة البيانات

```
View (HTML) ← المستخدمة تتفاعل ← POST/GET للـ Router
    ← Controller يستدعي Model
    ← Model يستعلم MySQL عبر PDO
    ← Controller يمرر النتائج للـ View
```

---

### مثال: عملية تسجيل مستخدمة جديدة

```php
// 1. View: نموذج يرسل POST لـ /register
// 2. AuthController::handleRegister()
csrf_verify();  // التحقق من رمز CSRF أولاً

$first_name = trim($_POST['first_name'] ?? '');
$last_name  = trim($_POST['last_name']  ?? '');
$email      = trim($_POST['email']      ?? '');
$password   = $_POST['password']        ?? '';

// التحقق من قوة كلمة المرور (8+ أحرف، كبير، صغير، رقم، رمز خاص)
if (!preg_match('/^(?=.*[a-z])(?=.*[A-Z])(?=.*[0-9])(?=.*[!@#$%...]).{8,}$/', $password)) {
    $error = "كلمة المرور يجب أن تحتوي على 8 أحرف على الأقل...";
}

// 3. UserModel::create() — Prepared Statement
$hash     = password_hash($password, PASSWORD_DEFAULT);
$fullName = $first_name . ' ' . $last_name;
$this->query(
    'INSERT INTO users (name, email, password) VALUES (?, ?, ?)',
    [$fullName, $email, $hash]
);

// 4. إرسال إيميلات تلقائية
EmailService::sendWelcome($fullName, $email);
EmailService::sendNewUserNotification($fullName, $email);
```

**تفاعل المستخدمة:** الضغط على الإعجاب يستدعي Fetch API فوراً ويحدث عداد الإعجاب دون أي تحميل.

- **المنشورات:** جدول المنشورات مع نافذة معاينة وخيار الحذف

| Fetch API مع الأمان | إجراء الإعجاب والحفظ دون تحميل الصفحة مع الحفاظ على الأمان | بناء نقاط API منفصلة في مجلد `api/` ترجع JSON وتتحقق من الجلسة في كل طلب |

| نظام الأدوار (Roles) | منع المستخدمة العادية من الوصول لصفحات المدير | دالة `requireAdmin()` في Base Controller تتحقق من `$_SESSION['user_role']` وترفض الوصول بخطأ 403 |

### الأخطاء التي تم اكتشافها وإصلاحها

- **مسار Router:** كان المشروع يعمل على مسار متداخل (`/malath-php-app/`) مما يسبب اختلافاً في URI — تم حله بتنظيف الـ URI في `Router::dispatch()`.
- **Collation Mismatch:** فرق في ترميز جداول `post_comments`, `post_likes`, `post_saves` (تستخدم `utf8mb4_general_ci`) عن بقية الجداول (`utf8mb4_unicode_ci`) أسبّب أخطاء في UNION queries — تم إصلاحه بإضافة `COLLATE` صريح.
- **هيكل جدول `notifications`:** كان الجدول بهيكل قديم ناقص بدون `actor_id` و`type` — تم تحديثه بـ `ALTER TABLE`.
